# おがわ歯科 シフト管理アプリ 仕様書（v1）

作成日: 2026-09-30
状態: v1 実装済み。使い方は [README.md](../README.md)。

## 一言でいうと

スタッフが共有PCで希望休・有給を入力し、管理者がそれを反映した月のシフト表を作って確定するアプリ。常勤の休み（祝日以外に月8日）はアプリが自動で割り振る。

## 前提（現状の運用）

- 資料: 2026年4〜8月のシフト表（Excel）、2026年9月のアポ帳の画面。
- 診療は日曜も含む毎日。祝日は休診。お盆などは「急患対応」で一部のスタッフだけ出勤する。
- 診療時間: 平日・土曜 9:00〜13:00／14:30〜18:00、日曜 9:00〜12:00／13:30〜17:00。
- シフトは1か月前までに確定する（例: 11月分を9月末に作る）。

## 決定事項（2026-09-30 の質問への回答）

| 項目 | 決定 |
|---|---|
| 仕組み | 共有PCの中だけで動く（HTML ファイル。データはブラウザ内に保存） |
| 確定の流れ | 締切後に管理者が調整して確定 |
| 自動作成の範囲 | 常勤の休日の割り振りまで自動 |
| 人数の条件 | 曜日ごとの推奨人数は使わず、最少人数だけを使う（Dr1・DH2・DA1・受付1・CS1） |
| 本人確認 | 名前を選ぶだけ（管理者画面のみパスワード） |
| 8日の数え方 | 半日勤務は0.5日の休み。休診日（祝日以外）は8日に含める。有給は含めない。研修は出勤扱い |
| 割り振りのルール | 連勤の上限・土日休みの公平・月内の分散・出勤人数の平均化をすべて考慮 |
| 締切 | 前々月の25日（例: 12月分は10月25日） |
| 有給 | 取得日の記録だけ（残日数の管理はしない） |

## 実装時に決めた前提

- 最少人数は午前・午後それぞれで判定する。ただし CS は「1日に1人以上」で判定する。
  - 理由: CS はパートが午前だけ・午後だけ・16時からなどで入っており、月曜の午前や金曜の午前に CS がいない日が毎週ある。
  - 職種ごとに「設定」で切り替えられる。
- DA と受付の兼任者は、足りない方の職種に数える（二部マッチングで判定）。
- 自動で休みを割り振るのは常勤だけ。パート・非常勤は基本パターンどおりに出勤する。
- ある職種がすでに足りない日でも、別の職種の人の休みは止めない（「その人が休むと不足が増えるか」で判定）。
- 途中入職・退職・産休・育休の月は、常勤の休みを在籍日数で日割りする（0.5日単位）。
- 下書きを作り直しても、管理者が手で直したマスは残す（外すこともできる）。
- 確定の期限は前月1日。過ぎても確定していなければ画面に表示する。
- 連勤の上限の初期値は5日（6連勤を作らない）。

## 画面

| タブ | 使う人 | 内容 |
|---|---|---|
| シフト表 | 全員 | 確定した月の表を見る・印刷する |
| 希望休・有給の入力 | 全員 | 名前を選び、カレンダーの日付を押して入力する。同じ職種で同じ日に休み希望を出している人数も見える |
| 管理者 → シフト作成 | 管理者 | 診療日の設定、申請の一覧、下書きの自動作成、マスの修正、確定、印刷、CSV 書き出し |
| 管理者 → スタッフ | 管理者 | 名前・職種（複数可）・常勤／パート・曜日ごとの基本パターン・入職日・退職日・休職期間 |
| 管理者 → 設定 | 管理者 | 最少人数と数え方、休みの日数、連勤の上限、締切日、診療時間、パスワード |
| 管理者 → バックアップ | 管理者 | データのファイル保存と復元 |

## データ

- 保存先: ブラウザの localStorage（キー `ogawa-shift-v1`）。
- スタッフ: 名前、職種（Dr・DH・DA・受付・CS・DT）、雇用（常勤／パート）、基本パターン（曜日ごとに 終日／AM／PM／時間指定／固定休／勤務なし）、入職日、退職日、休職期間（産休・育休・休職・その他）。
- 月ごと: 診療日の設定（休診・午前のみ・午後のみ・急患対応・特記事項）、申請、シフト、状態（下書き／確定）。
- スタッフの実名はリポジトリに入れない。初期データのファイルは管理者が直接読み込む。

## やらないこと（v1 の範囲外）

- 複数の端末での共有・スマホからの入力（共有PCだけで使う）
- 有給の残日数・付与日の管理
- 曜日ごとの推奨人数
- 月をまたいだ土日休みの公平さ（v1 は月の中だけで公平にする）
- 給与計算・勤怠（打刻）との連携

## 今後の検討

1. 11月・12月分で実際に使い、自動割り振りの結果と手直しの量を記録する。
2. 手直しが多い点を、ルールの重みや設定項目に反映する。
3. 複数の端末で使いたくなったら、Google スプレッドシート連携などクラウド保存を検討する。
